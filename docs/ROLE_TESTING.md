# Roles, visibility and manual testing

The table describes the current backend permissions. Department staff read access is broad across the registry; it is not restricted to their office. Survey/valuation writes and registrar approvals are constrained by the linked officer and office. Finalized records, ownership history and audit rows cannot be edited directly through the application, even by administrators.

| Role              | Can see                                                                                                                                                                       | Can create/change                                                                                                                                                                            | Cannot do                                                                                                                                                                         |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Administrator     | All registry records, private owner details, documents, audits, accounts and ER schema                                                                                        | Manage master data; create accounts; create/edit permitted records; select the correct registrar to verify/review/issue; controlled training import; remove unfinalized unreferenced records | Bypass finalized-history guards or directly change protected ownership/approval fields                                                                                            |
| Owner             | Current holdings or parcels linked to own applications and related records; own applications; all district/office names; owner names with other owners' private fields hidden | Submit pending property/registration/transfer/application records; upload documents and add parties on accessible pending transactions; offer only own transferor share                      | Approve/verify; enter surveys, valuations, tax receipts, claims or mutations; manage staff/accounts; view unrelated parcels or audits                                             |
| Survey officer    | Department registry records and uploaded documents, including owner details and officer profiles; ER schema                                                                   | Create surveys using own officer profile for own office's properties; edit own Scheduled surveys; completing a survey updates the latest parcel measurement                                  | Change other officers' work, write valuations, approve deeds/transfers, edit Completed surveys, remove records, manage accounts or view audits                                    |
| Valuation officer | Department registry records/documents and owner details; ER schema                                                                                                            | Create a new valuation using own officer profile for a property assigned to own office                                                                                                       | Edit finalized valuation history, write surveys, approve deeds/transfers, remove records, manage accounts or view audits                                                          |
| Sub-registrar     | Department registry records/documents, private owner details, audit trail and ER schema                                                                                       | Enter owners, properties, transactions, parties, documents, tax receipts, claims, mutations and applications; verify/review/issue only through own office's registrar profile                | Manage districts/offices/officers/accounts; survey or valuation writes; remove records; bypass ownership/deed/claim checks                                                        |
| Bank verifier     | All properties with registration status, districts/offices, ownership history, owner names, encumbrances and certificates; ER schema                                          | Read-only verification views                                                                                                                                                                 | See private owner ID/address/phone/email; download documents; access transactions, surveys, valuations, tax payments, applications, officers, audits or accounts; change anything |
| Auditor           | Registry records, private owner details, documents, audit trail and ER schema                                                                                                 | Read-only inspection                                                                                                                                                                         | Change/approve/remove records or manage accounts                                                                                                                                  |
| Public user       | Registered-property survey number, type, area, district/state and registration-office/date/status                                                                             | Create own read-only account through public signup                                                                                                                                           | Precise locations, owners, documents, claims, finances, history, staff, accounts, audits, schema, pending parcels or export/edit controls                                         |

The sub-registrar's general data-entry permissions currently use department-wide readable records; office jurisdiction is enforced for verification, approvals and certificate issuance. Public directory access is substantially narrower than department read access. Bank verifier is an external verification role and does not use an `officers` profile in the approved schema; an owner uses an `owners` profile. The four officer-profile roles are Survey officer, Valuation officer, Sub-registrar and Auditor.

## Creating a synchronized officer account

1. Administrator → username menu → **User accounts → Add user account**, or **Officers → Add officer account**.
2. Choose one of the four officer-profile roles.
3. Select **Create officer with this account**, enter the officer's full name and select an existing office. Add optional email/phone and choose a private password.
4. The server fixes designation to the selected role and saves officer + login + office link + audit events in one serializable transaction. A failed account insert leaves no new officer row.
5. For imported/historical profiles, use **Link an existing officer without a login**, or open that officer and choose **Create linked officer account**. Existing IDs/work references are retained. A profile already linked to a login cannot receive a second login through this flow; concurrent requests are checked too.
6. Account listings show officer and office names; administrator officer details show the linked username/status. Changing an officer's Active setting synchronizes its account and rejects existing sessions while inactive. Referenced work prevents changing the profile's designation/office and invalidating history.

The imported demonstration contains historical officer profiles without passwords/logins. They are retained for existing surveys, valuations and approvals, and administrators can link their accounts privately. No passwords are generated or published for those profiles. Trusted demo/import initialization retains sample profiles; ordinary application entry creates new profiles only with their accounts. No schema change was required: `users.officer_id → officers.id → offices.id` remains the authoritative link.

## Suggested manual checks

| Test                      | Action                                                               | Expected                                                                                           |
| ------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Nested navigation         | Property → ownership → owner → related holding; use Back/breadcrumbs | Return to the previous detail without losing the record list; linked fields open permitted records |
| Related-entry navigation  | Property → add document/transaction/survey; Cancel or save           | Return to the property's detail; a successful child save refreshes the parent                      |
| Office context            | Office → officer → work → property                                   | Correct linked records; Back path remains available                                                |
| ER inspector              | Click Inspect attributes on any table, then a relationship and Back  | All live columns/types/PK/FK/defaults/constraints shown in a visible panel on desktop or mobile    |
| Account/profile atomicity | Create a staff login with an already used username                   | Conflict; no extra officer profile                                                                 |
| Profile identity          | Choose Survey officer and an office; create account                  | New officer has survey designation and selected office; account points to its ID                   |
| Legacy link               | Link an existing sample officer and open its old work                | Same officer ID and historical links; no duplicate profile                                         |
| Own officer               | As survey/valuation user, attempt another officer's identity         | Rejected                                                                                           |
| Own office                | As survey/valuation user, choose a parcel from another office        | Rejected or wrong-office choices filtered                                                          |
| Registrar office          | Verify/approve/issue for another office                              | Rejected                                                                                           |
| Inactive account          | Administrator sets linked officer Inactive                           | Login/session rejected; account flag follows profile                                               |
| Unavailable permissions   | Test the Cannot do column for each role                              | UI hides controls; backend rejects direct attempts                                                 |
